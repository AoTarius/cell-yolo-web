# 自由绘图 MVP 设计说明

## 1. 目标
- 提供一个独立的“自由绘图”子界面，允许熟悉 Python 的用户基于自己任务数据进行自定义绘图。
- 在保证安全前提下，逐步落地从“页面骨架”到“安全执行后端”。

## 2. 范围（MVP）
- 前端：
  - 新增自由绘图页面。
  - 每次进入页面弹出“使用说明与限制”提示。
  - 提供脚本编辑区、运行按钮、输出区、图片展示区（先占位）。
- 后端（下一阶段接通）：
  - 新增安全执行接口，仅返回绘图结果和日志。
  - 严格限制用户只能访问本人任务数据。

## 3. 权限与安全要求
- 数据权限
  - 所有请求都基于当前登录用户身份验证。
  - 执行前校验任务归属：任务必须属于当前用户。
- 执行安全
  - 仅允许白名单库：numpy、pandas、matplotlib、seaborn、scipy。
  - 禁止 import 非白名单模块。
  - 禁止文件系统、网络访问、系统命令、动态执行（exec/eval/compile/__import__）。
  - 每次运行限制 CPU、内存、超时和输出大小。
- 输出安全
  - 仅允许返回文本日志与图片二进制（png/svg）。
  - 屏蔽服务端路径与系统环境细节。

## 4. 页面交互设计
- 入口
  - 从现有绘图页进入“自由绘图”，自动携带 taskId。
- 首次/每次进入提示
  - 弹窗说明：适用对象、数据范围、能力边界与限制条款。
  - 用户确认后进入编辑区。
- 运行流程（MVP）
  - 用户编写 Python 脚本 -> 点击运行 -> 展示日志与图片。

## 6. 后端接口建议（下一阶段）
- POST /api/free-plot/run/
  - 请求体
    - task_id: string
    - code: string
    - options: object（可选）
  - 返回
    - success: boolean
    - logs: string
    - image_base64: string（可选）
    - error: string（可选）

## 7. 执行器建议（下一阶段）
- 方案 A（推荐）
  - 独立容器执行：每次请求在短生命周期容器中运行。
  - 容器默认只读文件系统、禁外网、资源限制。
- 方案 B（过渡）
  - 受限子进程 + ast 检查 + 运行时限制。
  - 安全性低于容器方案，仅用于开发期。

## 8. 风险与缓解
- 风险：恶意脚本绕过限制。
  - 缓解：多层防护（AST 检查 + 白名单 + 沙箱隔离 + 资源限制）。
- 风险：高并发导致执行堆积。
  - 缓解：任务队列、并发上限、超时终止、熔断策略。
- 风险：图像数据过大影响响应。
  - 缓解：限制分辨率、压缩编码、响应体大小上限。

## 9. 验收标准（MVP）
- 可从绘图页进入自由绘图页。
- 每次进入都会弹出功能说明与限制。
- 页面包含编辑区、运行区与结果区。
- 页面不暴露危险能力入口。
