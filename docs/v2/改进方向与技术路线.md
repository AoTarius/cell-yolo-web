# CellTrack Web 改进方向与技术路线

> 基于当前项目（YOLOv8 + DeepSORT）的技术现状，梳理可落地的改进方向。
> 只保留**最高优先级**和**高优先级**项目，长期关注型不纳入。

---

## 当前技术栈

```text
视频帧 → YOLOv8 (检测/分割) → DeepSORT (跟踪匹配) → 带 ID 的细胞轨迹
```

- **检测器**：YOLOv8（Ultralytics，本地库 `web/libs/ultralytics`）
- **跟踪器**：DeepSORT（deep-sort-realtime 1.3.2）
- **已实现备用方案**：HFM-Tracker（因 C 扩展编译与硬件要求暂未启用，详见 `docs/v2/HFMTracker技术笔记.md`）

---

## 改进方向总览

| 优先级 | 方向 | 类型 | 改动范围 | 预期收益 |
|--------|------|------|----------|----------|
| 🔥🔥🔥 | YOLOv8 → YOLOv11 | 检测器升级 | 换权重 + 少量适配 | 参数减少 22%，mAP 提升 ~1.3%，小目标检测增强 |
| 🔥🔥🔥 | DeepSORT → ByteTrack | 跟踪器替换 | 替换跟踪模块 | MOTA +10~16%，无需 ReID 模型，省 GPU 显存 |
| 🔥🔥 | ByteTrack → OC-SORT | 跟踪器升级 | 替换跟踪模块 | 遮挡/非线性运动场景更鲁棒 |
| 🔥🔥 | HFM-Tracker 条件启用 | 细胞专用方案 | C 扩展预编译 + Web 封装 | 细胞轮廓级精度，自适应匹配，原生分裂处理 |

## 一、检测器升级：YOLOv8 → YOLOv11 🔥🔥🔥

### 为什么升级

| 对比维度 | YOLOv8（当前） | YOLOv11 |
|----------|---------------|---------|
| 参数效率 | 基准 | **减少 22%**，同精度下模型更小 |
| mAP (COCO) | 基准 | **+1.3%** |
| 小目标检测 | FPN + PAN 多尺度融合 | 新增 **C2PSA 空间注意力**，小目标更友好 |
| 生态兼容 | Ultralytics 框架 | **完全兼容**，API 一致 |

### 对细胞追踪的价值

- **C2PSA 模块**（Cross-Stage Partial Spatial Attention）：轻量空间注意力，让小细胞、密集细胞检测更准。
- **C3k2 CSP 瓶颈层**：混合 3×3 和 5×5 卷积核，对不同尺度细胞适应性更好。
- **Hybrid Task-Aware Label Assignment**：改善拥挤场景下的标签分配，减少密集细胞的漏检。

### 落地方式

```text
1. pip install ultralytics --upgrade  （或更新本地 libs/ultralytics）
2. 下载 YOLOv11 预训练权重
3. 在细胞数据集上微调（或用现成权重直接推理）
4. 替换 video_processor.py 中的模型加载路径
```

**改动范围**：极小（~10 行代码），主要是权重路径切换。

## 二、跟踪器替换：DeepSORT → ByteTrack 🔥🔥🔥

### 为什么替换

| 对比维度 | DeepSORT（当前） | ByteTrack |
|----------|-----------------|-----------|
| MOTA (MOT17) | ~61-70% | **~76-80%** |
| 速度 | ~40 FPS | **~45 FPS (Python)** |
| 外观特征模型 | ✅ 需要 ReID CNN | ❌ **不需要** |
| GPU 显存占用 | 额外加载 ReID 模型 | 无额外模型 |
| 细胞外观相似的场景 | ReID 特征区分度低，易 ID 切换 | **不依赖外观，更鲁棒** |

### 为什么 ByteTrack 对细胞追踪更好

DeepSORT 的核心优势是**外观重识别（ReID）**——人能通过衣服颜色、体型找回被遮挡的人。但细胞追踪场景下：

- 同种细胞**外观高度相似**，ReID 特征的区分度有限。
- DeepSORT 的 128 维 CNN 特征是**在行人数据集上训练的**，对显微镜细胞图像泛化能力存疑。

ByteTrack **完全抛弃外观特征**，转而依赖一个更聪明的策略：**保留低置信度检测框**。

### ByteTrack 的核心机制

```text
传统跟踪器（DeepSORT）：
  所有检测框 → 按置信度阈值过滤 → 只保留高分框 → 匹配轨迹
  ❌ 被遮挡/模糊的细胞因置信度低被丢弃，轨迹断裂

ByteTrack：
  所有检测框 → 高分框先匹配（可靠） → 低分框再匹配（召回）
  ✅ 被遮挡的细胞即使置信度低，也有机会匹配到已有轨迹
```

### 落地方式

```text
1. pip install bytetrack  （或集成 boxmot 库，同时支持多种跟踪器）
2. 将 video_processor.py 中的 DeepSORT 调用替换为 ByteTrack
3. 调参：置信度阈值（高分/低分分界线）、匹配 IoU 阈值
```

**改动范围**：中等（跟踪模块替换，约 50-100 行代码），接口兼容 tracking-by-detection 范式。

## 三、跟踪器升级：OC-SORT 🔥🔥

### 定位

ByteTrack 的增强替代，适用于**细胞频繁交叉、遮挡严重、运动不规则**的场景。

### 与 ByteTrack 的对比

| 对比维度 | ByteTrack | OC-SORT |
|----------|-----------|---------|
| 核心机制 | 保留低置信度框二次匹配 | **ORU 回溯修正** + 低置信度匹配 |
| 遮挡处理 | 低分框仍然可以匹配 | 目标重现时**回溯修正整条轨迹**，减少漂移 |
| 非线性运动 | 卡尔曼滤波线性预测 | 方向一致性匹配 + 自适应运动补偿 |
| MOTA | ~76-80% | ~73.9%（略低，但 IDF1 和身份保持更好） |
| 适合场景 | 通用 | 大量遮挡、快速变向、细胞交叉 |

### OC-SORT 的核心机制：ORU（Observation-Centric Re-Update）

```text
DeepSORT/ByteTrack：
  目标被遮挡 → 卡尔曼预测继续"猜测"位置 → 偏差累积
  → 目标重新出现时，预测位置与实际位置偏差大 → 匹配失败 → ID 切换

OC-SORT：
  目标被遮挡 → 卡尔曼预测继续"猜测"
  → 目标重新出现 → 匹配成功 → 回溯修正：用新观测修正被遮挡期间的轨迹
  → 轨迹更平滑，ID 更稳定
```

### 决策建议

- 如果细胞视频中**遮挡较少、运动较规则** → ByteTrack 足够。
- 如果细胞视频中**频繁交叉、密集迁移** → OC-SORT 更优。

两者可以共存：`boxmot` 库同时支持 ByteTrack 和 OC-SORT，通过参数切换。

## 四、HFM-Tracker 条件启用 🔥🔥

### 定位

**专为细胞设计的检测+跟踪一体化算法**，已在本项目中实现核心算法。待工程条件成熟后作为可选追踪引擎启用。

### 与当前方案的核心差异

| 维度 | YOLOv8 + DeepSORT | HFM-Tracker |
|------|-------------------|-------------|
| 检测方式 | 矩形边界框 | **多边形轮廓**（八边形 + Level Set） |
| 特征利用 | 运动 + CNN 外观 | **形态 + 混合运动**（GIoU + 距离 + 面积） |
| 匹配策略 | 级联匹配，手动调权 | **两阶段自适应**，无需手动调权 |
| 细胞分裂 | 需额外逻辑 | **原生支持** |
| MOTA（细胞数据） | — | **75.4%**（优于 ByteTrack 的 73.5%） |

### 暂未启用的原因

| 障碍 | 说明 |
|------|------|
| **C 扩展编译** | 核心模块（环形卷积、Level Set、ACM）依赖 C/C++ 底层实现，Windows/macOS/Linux 需分别编译动态库 |
| **硬件门槛** | CA 轮廓检测 + Level Set 计算量大，推荐 32GB RAM |
| **项目理念** | 目标用户（科研人员）应能一键安装使用，不应要求安装编译工具链 |

### 启用前置条件

```text
□ 为 Windows/macOS/Linux 预编译 C 扩展动态库
□ 模型量化和推理优化降低硬件门槛（目标：16GB RAM 可运行）
□ 完成 CA + ACM 流程的 Web API 封装
□ 前端新增"追踪方法"下拉选项（YOLOv8+DeepSORT / HFM-Tracker）
□ 添加硬件检测逻辑，低配设备自动推荐轻量方案
```

## 建议实施路线

```text
第 1 步（短期，1-2 周）：
  ├── YOLOv8 → YOLOv11 升级（换权重，风险极低）
  └── DeepSORT → ByteTrack 替换（换跟踪器，立竿见影）
      预期效果：检测更准 + 跟踪更稳 + 显存占用更低

第 2 步（中期，1 个月）：
  └── 根据细胞数据特点，评估是否需要 OC-SORT 替代 ByteTrack
      触发条件：ByteTrack 在遮挡/交叉场景下 ID 切换仍较多

第 3 步（长期，持续推进）：
  └── HFM-Tracker C 扩展预编译 + Web 封装，作为可选引擎提供
      目标：用户可在前端一键切换追踪方法
```
