# YOLOv8 与 DeepSORT 论文复习笔记

资料来源：

- `yolo.pdf`：*What is YOLOv8: An In-depth Exploration of the Internal Features of the Next-generation Object Detector*
- `deepsort.pdf`：*Simple Online and Realtime Tracking with a Deep Association Metric*

> 这份笔记用通俗语言整理两篇论文的核心思想。可以把 YOLOv8 理解为“每一帧里找出目标在哪里、是什么”，把 DeepSORT 理解为“把不同帧里的同一个目标串起来，尽量不要认错人”。

## 1. 两个技术解决的问题不同

| 技术 | 主要任务 | 输入 | 输出 | 关键能力 |
|---|---|---|---|---|
| YOLOv8 | 目标检测 | 一张图片或视频的一帧 | 目标框、类别、置信度 | 快速、准确地找到目标 |
| DeepSORT | 多目标跟踪 | 每一帧的检测框 | 带 ID 的目标轨迹 | 在遮挡、漏检后尽量保持身份一致 |

如果做视频中的行人、车辆、物体跟踪，常见流程是：

1. 用 YOLOv8 对每一帧做检测，得到目标框。
2. 把目标框送入 DeepSORT。
3. DeepSORT 根据运动位置和外观特征判断“这个框是不是上一帧的同一个目标”。
4. 输出带编号的轨迹，例如 `person-3` 从第 1 帧一直走到第 100 帧。

## 2. YOLOv8：实时目标检测

### 2.1 YOLO 的基本思想

YOLO 是 “You Only Look Once” 的缩写，意思是“只看一遍”。传统检测方法可能先找候选区域，再逐个分类；YOLO 则把检测看成一个端到端的预测问题：一张图进入神经网络，网络直接输出目标的位置和类别。

通俗地说，YOLO 做了三件事：

1. 看整张图，提取特征。
2. 判断图中哪些位置可能有目标。
3. 给每个目标预测边界框、类别和置信度。

它的优点是速度快，因此适合视频监控、自动驾驶、工业检测、无人机巡检等实时场景。

### 2.2 YOLOv8 的三个核心模块

YOLOv8 仍然可以按 `Backbone -> Neck -> Head` 理解。

| 模块 | 中文理解 | 作用 |
|---|---|---|
| Backbone | 主干网络 | 从图片中提取特征，例如边缘、纹理、形状、语义信息 |
| Neck | 特征融合层 | 把不同尺度的特征融合起来，帮助同时检测大目标和小目标 |
| Head | 检测头 | 输出最终目标框、类别和置信度 |

#### Backbone：负责“看懂图片”

论文强调 YOLOv8 使用 CSPNet / CSPDarknet 相关思想来增强特征提取。CSP 的核心价值是减少重复计算，同时保留有效特征。可以理解为：网络不把所有信息都重复走一遍，而是分流、融合，从而提升效率。

#### Neck：负责“融合不同大小的目标信息”

YOLOv8 使用 FPN + PAN / PANet 思想。

- FPN 偏向自上而下，把高层语义信息传给低层特征。
- PAN 偏向自下而上，把低层定位信息再传回高层。

这样做的原因是：小目标需要精细位置，大目标需要强语义理解。多尺度融合可以让模型既看得清小物体，也能理解大物体。

#### Head：负责“给出最终检测结果”

检测头根据融合后的特征输出：

- 边界框坐标；
- 类别概率；
- 目标存在的置信度。

YOLOv8 的重要变化是采用 anchor-free 思路。

### 2.3 Anchor-free 是什么

早期 YOLO 版本常使用 anchor box。Anchor box 可以理解成一些预设形状的框，比如“高瘦框”“宽扁框”“中等框”。模型不是从零预测框，而是在这些预设框的基础上修正。

Anchor-free 则不再依赖大量预设框，而是更直接地预测目标框。优点包括：

- 超参数更少，不需要手工设计 anchor；
- 对不同长宽比的目标更灵活；
- 训练流程更简洁；
- 计算复杂度更低。

通俗地说，anchor-based 像是“先拿几个模板框去套目标”，anchor-free 更像是“直接判断目标中心和边界在哪里”。

### 2.4 YOLOv8 的训练方法

#### 数据增强

论文提到 Mosaic 和 Mixup。

- Mosaic：把多张图片拼在一起训练，让模型在一张训练图里看到更多目标、尺度和背景。
- Mixup：把不同图片按比例混合，让模型学会更稳健的特征。

这些方法能提升泛化能力，特别是对小目标、复杂背景、不同尺度目标更有帮助。

#### Focal Loss

目标检测数据经常存在类别不平衡：容易样本很多，困难样本较少。Focal Loss 的思想是让模型少花精力在“已经很容易分对”的样本上，多关注难样本。

例如，清晰的大车很容易识别，远处被遮挡的小人更难识别。Focal Loss 会提高后者在训练中的权重。

#### IoU Loss

IoU 表示预测框和真实框的重叠程度。重叠越多，IoU 越高。IoU Loss 用来优化定位效果，让预测框更贴近真实目标。

#### Mixed Precision Training

混合精度训练使用 16 位浮点数和 32 位浮点数配合训练。它的主要好处是：

- 训练更快；
- 显存占用更小；
- 可以使用更大的 batch size；
- 在合适硬件上基本不明显损失精度。

### 2.5 YOLOv8 模型大小选择

YOLOv8 有多个规模：

| 模型 | 特点 | 适合场景 |
|---|---|---|
| YOLOv8n | 最小最快，精度较低 | 边缘设备、移动端、实时性要求极高 |
| YOLOv8s | 速度和精度较均衡 | 普通实时检测任务 |
| YOLOv8m | 中等规模，精度更好 | 有一定算力、要求更高精度 |
| YOLOv8l | 大模型，高精度 | 医学影像、自动驾驶等复杂场景 |
| YOLOv8x | 最大、最精确、最耗算力 | 高端 GPU、工业检测、安防精细识别 |

模型越大，一般精度越高，但速度越慢、显存和算力要求越高。实际选型时不能只看准确率，还要看部署设备能不能跑得动。

### 2.6 YOLOv8 标注格式

YOLOv8 常用 TXT 标注格式：

```text
<class> <center_x> <center_y> <width> <height>
```

其中坐标都是归一化值，范围通常是 0 到 1。

示例：

```text
0 0.492 0.403 0.212 0.315
```

含义是：

- 类别编号为 0；
- 目标中心点在图片宽度的 49.2%、高度的 40.3%；
- 目标框宽度占图片宽度的 21.2%；
- 目标框高度占图片高度的 31.5%。

### 2.7 YOLOv8 的优点与局限

优点：

- 检测速度快，适合实时任务；
- anchor-free 简化训练和部署；
- 多尺度特征融合让小目标检测更好；
- 模型规模丰富，便于按硬件选择；
- Python 包和 CLI 降低使用门槛。

局限：

- 大模型对 GPU 要求高；
- 小模型在复杂场景下精度有限；
- 目标严重遮挡、极小目标、低光照场景仍可能漏检；
- 检测只处理单帧，不天然解决跨帧身份保持问题。

## 3. DeepSORT：多目标跟踪

### 3.1 SORT 的基本思想

DeepSORT 是 SORT 的增强版。SORT 的全称是 Simple Online and Realtime Tracking，意思是简单、在线、实时的多目标跟踪。

SORT 的核心流程：

1. 检测器给出当前帧的目标框。
2. 卡尔曼滤波预测上一帧目标在当前帧可能出现的位置。
3. 用匈牙利算法匹配“预测轨迹”和“当前检测框”。
4. 匹配成功则更新轨迹，匹配失败则新建或删除轨迹。

SORT 很快，但有一个问题：它主要靠位置和框重叠来匹配。如果人被遮挡几帧，再出现时位置变化较大，SORT 容易把 ID 弄错。

### 3.2 DeepSORT 增加了什么

DeepSORT 的关键改进是加入 deep association metric，即深度外观关联度量。

简单说，DeepSORT 不只看“目标在哪里”，还看“目标长什么样”。

它会用一个 CNN 为每个检测框提取外观特征，例如衣服颜色、纹理、整体视觉特征等。然后在匹配时同时考虑：

- 运动信息：目标按上一帧速度推测应该在哪里；
- 外观信息：这个检测框看起来像不像之前那个目标。

这使得 DeepSORT 在遮挡、短暂漏检、目标交叉时更不容易换 ID。

### 3.3 卡尔曼滤波：预测目标位置

DeepSORT 使用 8 维状态：

```text
(u, v, γ, h, u_dot, v_dot, γ_dot, h_dot)
```

含义：

- `u, v`：目标框中心点坐标；
- `γ`：宽高比；
- `h`：高度；
- 后四项是对应的速度变化。

卡尔曼滤波做的事情可以理解为：根据目标过去的位置和速度，预测它下一帧大概会出现在哪里。检测结果来了以后，再用真实检测结果修正预测。

### 3.4 马氏距离：运动匹配

DeepSORT 用马氏距离衡量检测框和预测轨迹的位置是否合理。

通俗理解：如果某个检测框离预测位置太远，就认为它不太可能属于这条轨迹。

马氏距离的优点是考虑不确定性。比如目标刚刚被遮挡过，预测位置不确定性更大；距离判断时会考虑这种不确定性。

### 3.5 余弦距离：外观匹配

DeepSORT 用 CNN 提取每个目标框的 128 维外观特征，并做归一化。外观匹配用余弦距离：

- 距离小：外观相似，可能是同一个人；
- 距离大：外观差异大，可能不是同一个人。

每条轨迹会保存最近若干次外观特征，论文中提到保存最近 100 个特征。新检测框会和轨迹的历史特征比较，找最相似的一次。

### 3.6 关联代价：把运动和外观结合

DeepSORT 的匹配代价可以理解为：

```text
总代价 = λ * 运动距离 + (1 - λ) * 外观距离
```

如果摄像头运动很明显，运动预测可能不可靠，论文实验中设置 `λ = 0`，也就是主要依赖外观特征做匹配，但仍然用马氏距离作为门控，排除明显不可能的位置匹配。

### 3.7 Matching Cascade：优先匹配最近出现的轨迹

DeepSORT 不一次性把所有轨迹和检测框全部匹配，而是使用匹配级联。

它的思想是：刚刚出现过的轨迹预测更可靠，应该优先匹配；很久没出现的轨迹不确定性更高，后匹配。

这样可以减少遮挡后多个轨迹争抢同一个检测框导致的身份混乱。

### 3.8 轨迹管理

DeepSORT 会维护每条轨迹的状态：

- 新检测框如果没有匹配到旧轨迹，就新建一条 tentative 轨迹；
- 新轨迹需要连续几帧匹配成功，才会变成 confirmed；
- 如果轨迹太久没有匹配到检测框，超过最大年龄 `Amax`，就删除；
- 如果新轨迹在前几帧没有稳定匹配，也会被删除。

这套机制可以过滤偶然误检，也能处理目标离开画面的情况。

### 3.9 DeepSORT 的实验结论

论文在 MOT16 数据集上评估。与原始 SORT 相比：

- ID switches 从 1423 降到 781；
- 身份切换减少约 45%；
- DeepSORT 仍能保持实时运行；
- 相比 SORT，DeepSORT 速度略低，但身份保持明显更好。

这说明加入外观特征后，跟踪器更能在遮挡和漏检后认回同一个目标。

### 3.10 DeepSORT 的优点与局限

优点：

- 在线实时，不需要提前看到整段视频；
- 比 SORT 更能处理遮挡；
- 身份切换明显减少；
- 算法结构清晰，工程实现相对直接；
- 可与 YOLO 等检测器组合。

局限：

- 依赖检测器质量，漏检和误检会影响跟踪；
- 外观特征主要对行人重识别有效，换到其他目标可能需要重新训练；
- 拥挤场景、长时间遮挡、外观相似目标仍可能 ID 错乱；
- 需要 CNN 提取特征，速度比原始 SORT 慢。

## 4. YOLOv8 + DeepSORT 的组合理解

YOLOv8 和 DeepSORT 经常一起用，因为它们刚好补齐彼此：

| 环节 | 负责技术 | 说明 |
|---|---|---|
| 当前帧里有哪些目标 | YOLOv8 | 输出检测框和类别 |
| 这些目标是不是上一帧的人或车 | DeepSORT | 给检测框分配稳定 ID |
| 目标轨迹如何延续 | DeepSORT | 用卡尔曼滤波和外观特征维护轨迹 |

可以把整个系统理解成：

```text
视频帧 -> YOLOv8 检测 -> DeepSORT 匹配与更新 -> 带 ID 的目标轨迹
```

YOLOv8 检测越准，DeepSORT 的输入越可靠；DeepSORT 匹配越稳，最终视频轨迹越连续。

## 5. 常见考试或答辩问答

### Q1：YOLOv8 为什么适合实时检测？

因为 YOLO 系列把目标检测建模为单阶段任务，一次前向传播直接输出目标框和类别。YOLOv8 进一步通过高效主干网络、多尺度特征融合、anchor-free 预测和混合精度训练提升速度与精度。

### Q2：YOLOv8 的 Backbone、Neck、Head 分别做什么？

Backbone 提取图像特征，Neck 融合不同尺度特征，Head 输出边界框、类别和置信度。

### Q3：Anchor-free 的优势是什么？

不需要预设 anchor box，减少超参数和计算复杂度，对不同尺度、不同长宽比的目标更灵活，训练和部署更简单。

### Q4：DeepSORT 相比 SORT 的核心改进是什么？

DeepSORT 在 SORT 的运动匹配基础上加入了深度外观特征。SORT 主要看位置，DeepSORT 同时看位置和外观，因此遮挡后更容易保持同一 ID。

### Q5：DeepSORT 中卡尔曼滤波和匈牙利算法分别做什么？

卡尔曼滤波预测轨迹在下一帧的位置；匈牙利算法根据代价矩阵完成检测框和轨迹之间的最优匹配。

### Q6：为什么 DeepSORT 能减少 ID switch？

因为它保存目标的外观特征。当目标被遮挡或短暂消失后重新出现，即使位置预测不够准，也可以通过外观相似度把它和原来的轨迹重新关联起来。

### Q7：YOLOv8 + DeepSORT 系统的瓶颈在哪里？

主要瓶颈包括检测器误检漏检、外观特征提取耗时、目标长时间遮挡、目标外观高度相似，以及部署设备算力不足。

## 6. 复习速记

- YOLOv8：解决”这一帧里有什么、在哪里”。
- DeepSORT：解决”跨帧是不是同一个目标”。
- YOLOv8 关键词：单阶段检测、Backbone、FPN+PAN、anchor-free、Mosaic、Mixup、Focal Loss、IoU Loss、混合精度。
- DeepSORT 关键词：tracking-by-detection、卡尔曼滤波、匈牙利匹配、马氏距离、余弦距离、外观特征、匹配级联、ID switch。
- 组合流程：YOLOv8 检测框输入 DeepSORT，DeepSORT 输出带身份 ID 的轨迹。

## 7. 项目中的替代方案：HFM-Tracker

本项目还实现了一套**专门针对细胞追踪设计**的算法——HFM-Tracker（详见 [`HFMTracker技术笔记.md`](./HFMTracker技术笔记.md)）。

### 7.1 与 YOLOv8 + DeepSORT 的核心差异

| 维度 | YOLOv8 + DeepSORT | HFM-Tracker |
|------|-------------------|-------------|
| 检测方式 | 矩形边界框 | **多边形轮廓**（八边形 + Level Set 细化） |
| 特征利用 | 运动 + 128 维 CNN 外观 | **形态 + 混合运动**（GIoU + 距离 + 面积） |
| 匹配策略 | 级联匹配，手动调权 λ | **两阶段自适应匹配**，无需手动调权 |
| 设计目标 | 通用目标追踪 | **细胞专用** |

### 7.2 为什么当前默认使用 YOLOv8 + DeepSORT？

HFM-Tracker 已实现，但暂未作为 Web 应用的默认追踪引擎，原因在于：

1. **硬件要求较高**：CA 轮廓检测 + Level Set 后处理计算量大，推荐 32GB RAM，超出普通科研工作站的配置。
2. **C 语言编译依赖**：核心模块（环形卷积、Level Set、ACM）依赖 C/C++ 扩展，跨平台编译复杂。
3. **与”便捷可用”理念冲突**：项目面向科研人员，要求一键安装、纯 Python 生态。HFM-Tracker 的 C 扩展编译不符合这一要求。

待 C 扩展预编译、硬件优化完成后，HFM-Tracker 将作为可选追踪引擎在前端提供切换选项。
